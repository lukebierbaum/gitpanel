# M11 — Pull requests

**Goal:** review, check out, create and merge pull requests without leaving gitpanel — reusing what already exists (log, diff viewer, compare, cherry-pick, worktrees, console, undo) instead of rebuilding it. GitHub first, through the `gh` CLI the user is already logged into; GitLab (`glab`) can plug in later behind the same interface.

## Why inside gitpanel
A PR is a branch plus conversation. The branch part — commits, diffs, already-picked detection, checkout, worktrees, cherry-picking — is gitpanel's core; only the conversation part (description, checks, reviews, comments, merge) is new.

## Phases
| Phase | Scope | Size |
|---|---|---|
| **11a — Browse** | PR window: lists, details, checks, commits and files with gitpanel's diff viewer; checkout into a branch or a **new worktree**; open in browser; current-branch PR badge in the header | ≈ M3 |
| **11b — Act** | create PR from a branch (title/body drafted from its commits), review (approve / request changes / comment), comment, merge (merge / squash / rebase, delete branch, auto-merge), close / reopen, draft ↔ ready, re-run failed checks | ≈ M4 |
| **11c — Inline review** | review threads shown on diff lines, add a line comment, reply, resolve; pending (batched) review | ≈ M5 |
| 11d — GitLab (optional) | `glab` provider for the same interface | small |

## Backend — `gitpanel/forge/` (no Textual, like `gitpanel/git/`)
| Module | Contents |
|---|---|
| `runner.py` | `Gh` — runs `gh … --json` with `GH_PROMPT_DISABLED=1`, parses JSON, maps errors (not installed, not logged in, no repo, rate limit) to `ForgeError` with a fix-it message; every call reports to `CONSOLE` (kind `"gh"`) so it shows in the Console |
| `provider.py` | `ForgeProvider` protocol; `detect(session)` picks GitHub when a remote points at a host `gh auth status` knows (github.com or GHE) |
| `models.py` | `PullRequest` (number, title, author, state, draft, head/base, head sha, adds/dels, files, review decision, mergeable, CI rollup, labels, reviewers, url, updated), `Check`, `Review`, `Comment`, `ReviewThread` |
| `github.py` | `list_prs(query)` (`gh pr list --search … --json …`), `pr(n)`, `checks(n)`, `comments(n)`, `create`, `review`, `comment`, `merge`, `close`, `reopen`, `ready`, `rerun_failed(n)`, `threads(n)` / `add_line_comment` / `resolve` (11c, via `gh api graphql`) |
| `git` side | `fetch_pr(session, n)` fetches `pull/N/head` into `refs/gitpanel/pr/N` so commits and diffs come from the local object store and reuse `log.py`, `patch.py` (`RangeDiff(merge-base, head)`), `cherry_pick.picked_shas`; checkout uses `gh pr checkout` (keeps fork remotes right), worktree checkout = fetch + `worktrees.add` |

Caching: PR lists are cached per query for 60 s (configurable); the PR window refreshes on open, on `ctrl+r`, after any PR action, and every few minutes while it is visible — never when hidden. Fetched PR heads are reused until the head sha changes.

## UI — tool window `7 PRs`
```
┌ Mine · Review requested · Assigned · Open · Closed   [ search: is:open label:bug ]┐
│ #482 ✓ Approved  Add parser fuzz tests        ada   feature/fuzz → main   2h  +120 −8 │
│ #479 ✗ Changes   Fix unicode in tokenizer      lin   bugfix/unicode → main 1d  ⎇ checked out │
│ #471 ● Pending   Draft: new CLI flags          you   feature/cli → main    3d  draft │
├───────────────────────────────────────────────────────────────────────────────┤
│ Overview │ Commits │ Files │ Checks                                            │
│ description (markdown) · labels · reviewers + their verdicts · comments        │
└───────────────────────────────────────────────────────────────────────────────┘
```
- **Overview:** rendered description, labels, reviewers and verdicts, mergeability, conversation.
- **Commits:** the log table for the PR's commits — already-picked marks against your branch, `C` cherry-picks as everywhere else.
- **Files:** changed-files list + the normal diff viewer (side-by-side, `n`/`p`), diff = merge-base(base, head)..head.
- **Checks:** each check with status and duration; `enter` opens its log in the browser; re-run failed.
- **Header badge:** when the current branch has a PR, the header shows `PR #479 ✗` (CI rollup).

## Actions (registry, screen `prs`, new `Scope.PR`)
| id | key | phase | notes |
|---|---|---|---|
| `pr.checkout` | `enter` | a | `gh pr checkout`; local changes → Smart/Force Checkout prompt |
| `pr.checkout_worktree` | `w` | a | fetch + new worktree at the PR head (path from `worktrees.path_template`), offer to switch |
| `pr.open_browser` | `o` | a | |
| `pr.copy_url` | `y` | a | |
| `pr.create` | `n` (also Branches popup / Log on a branch) | b | form: base, title, body (from commits), draft, reviewers |
| `pr.review` | `r` | b | form: approve / request changes / comment + body |
| `pr.comment` | `m` | b | multi-line prompt |
| `pr.merge` | `M` | b | choose merge / squash / rebase, delete branch, auto-merge when checks pass; confirm |
| `pr.close` / `pr.reopen` | — | b | confirm |
| `pr.ready` / `pr.draft` | — | b | |
| `pr.rerun_failed` | — | b | `gh run rerun --failed` for the PR's failing runs |
| `pr.line_comment` / `pr.reply` / `pr.resolve` | `c` / `R` / `x` (in Files) | c | |
| `app.show_prs` | `7` | a | |

Remote actions aren't undoable, so they confirm where they publish or merge; any local effect (checkout, worktree) still goes through the journal.

## Config
```toml
[prs]
refresh_seconds = 180      # while the PR window is visible; 0 = manual only
default_query = "mine"     # mine | review-requested | assigned | open
merge_method = "squash"    # default choice in the merge dialog
```

## Testing
A fake `gh` executable (Python script on `PATH` in tests) answers from JSON fixtures and records its arguments — no network in CI. Backend tests for parsing, errors and each command line; action tests with `FakeUi` (+ real git for checkout/worktree); pilot tests for the window, tabs and header badge.

## Out of scope (for now)
Issues, notifications, Actions logs inside gitpanel, multi-repo dashboards, editing PR descriptions in place (the create/edit form covers it).
