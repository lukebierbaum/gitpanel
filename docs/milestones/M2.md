# M2 — Log, commit graph, scripted rebase

**Goal:** PyCharm's Git Log tool window: a paged commit list with a coloured lane graph, ref/worktree labels, filters, commit details with changed files and diff, and the first history-editing actions — built on `scripted_rebase` so M6 (interactive rebase) and M10 (patch builder) reuse it.

**Out of scope:** cherry-pick (M4 — needs already-picked markers and cross-branch picking), interactive rebase editor / fixup / squash / drop (M6), branches popup (M3).

## Deliverables

### Backend (`gitpanel/git/`)
| Module | Contents |
|---|---|
| `log.py` | `LogFilter(refs, author, text, paths, since, until, first_parent, no_merges)`; `async def load_page(git, filt, skip, limit) -> list[Commit]` via `git log -z --topo-order` with a NUL/US-separated format; `commit_details(git, sha) -> Commit` (full body, committer); `containing_branches(git, sha)` |
| `graph.py` | `GraphBuilder` — incremental lane assignment across pages; `GraphRow(sha, column, cells)` where `cells` are `(char, lane_color)` pairs for `2·lanes` columns (node `●`/merge `◆`, `│`, `╮ ╭ ╯ ╰`, `─`, `┼`) |
| `markers.py` | `Marker`, `MarkerProvider` protocol; `RefMarkers` (HEAD, local/remote branches, tags), `WorktreeMarkers` (HEADs of other worktrees) |
| `refs.py` (start) | `list_refs(git) -> list[Ref]` from `for-each-ref`, `head_ref()` |
| `reset_revert.py` | `reset(git, sha, mode)`, `revert(git, shas)`, `checkout_detached(git, sha)` |
| `scripted_rebase.py` | per architecture §9: `TodoItem`, `todo_for()`, `run()`, `resume()`, `RebaseResult`; refuses ranges containing merges until `--rebase-merges` support (M6) |
| `_editor.py` | answers reword prompts from `messages.json` (already stubbed in M1) |

### Actions (`gitpanel/actions/builtin/log.py`, screen `log`, scope COMMIT)
| id | key | notes |
|---|---|---|
| `log.checkout_revision` | — | detached checkout; mutating |
| `log.new_branch` | `B` | prompt; `git switch -c <name> <sha>` |
| `log.new_tag` | `T` | prompt; lightweight tag |
| `log.reset` | — | choose soft/mixed/keep/hard; destructive (backup); journal `reset_mode` = chosen mode |
| `log.revert` | — | multi-select; conflicts → banner |
| `log.reword` | `F2` / `R` | multi-line prompt; HEAD → `commit --amend --only`, older → `scripted_rebase` |
| `log.copy_hash` | `y` | copies full sha(s) to the clipboard (OSC 52) |
| `app.show_commit` / `app.show_log` | `alt+0` / `alt+9` | PyCharm tool-window keys |

`Ui.prompt` gains `multiline: bool = False` (TextArea dialog) for commit messages.

### UI
- Tool-window tabs (`Commit`, `Log`) above the views; `alt+0` / `alt+9`.
- `widgets/commit_table.py` — Line-API table: graph | subject with markers | author | date; HEAD row bold; multi-select with `shift+↑↓`; loads the next page when the cursor nears the end.
- `screens/log.py` — filter bar (text/regex, branch, user, path, since; `/` focuses it, `enter` applies, `escape` clears), table, details (sha, author, dates, refs, contained in branches, full message), changed-files list, diff of the selected file.
- `DiffView` side-by-side mode (`s` toggles) — hunk-level selection only while side-by-side.

## Acceptance tests
1. `graph`: linear history → single lane; branch + merge → fork/merge glyphs in the right columns; octopus merge; lanes stay consistent across page boundaries.
2. `log.load_page` with each filter (author, grep, path, since, branch) and paging (`skip`) returns the expected commits; unusual subjects (unicode, `%`, separators) parse.
3. `markers`: HEAD, branch, remote, tag and other-worktree markers on the right shas.
4. `scripted_rebase`: reword a middle commit (rest of history identical apart from shas); `edit` stop with a callback that amends; conflict returns `status="conflict"` and `resume()` finishes after resolution; whole rewrite is one journal entry and `undo` restores the original branch.
5. Actions: reset (each mode) + undo; revert creates the inverse commit; reword HEAD and an older commit; new branch / tag from a commit.
6. Pilot: switch to Log with `alt+9`, select second commit, details show its message and files, `R` reword → message updated in the table.

## Definition of done
All tests + lint green locally and in CI; `pixi run start` on the demo repo shows the graph with the feature branch and worktree labels; architecture.md updated; pushed.

## As built
- Tool windows live in a `ContentSwitcher` under a `Tabs` bar; views implement `context()`, `hint_extras()`, `handle_event()`, `reload()`, `focus_default()` and a `stale` flag (inactive views reload when shown).
- `log.reword` on HEAD uses `commit --amend --only` (works with staged changes present); older commits use `scripted_rebase`. Both are one journal entry.
- `DiffView` side-by-side zips removal/addition blocks; line-range selection is unified-view only.
- Ref markers render as `[branch]`, the current branch as a filled badge, worktree HEADs as `⎇ name`.
- Theme: the user asked for a Hulk colour scheme — `gitpanel/ui/theme.py` defines `hulk` (default) and `hulk-light`; lane colours start with greens and purples.
