# M3 — Branches popup, Worktrees, remotes, tags

**Goal:** PyCharm's Branches popup and Git push/update flows, plus a first-class **Worktrees** tool window (user's tier-1 priority) with worktree awareness everywhere.

## Backend
| Module | Contents |
|---|---|
| `refs.py` | `branches(git) -> list[BranchRef]` (local + remote, upstream, ahead/behind, last commit date, checked-out-in-worktree); `recent_branches()` from the HEAD reflog; `Favorites` (shared private dir); `checkout`, `checkout_remote` (creates/uses tracking branch), `create`, `rename`, `delete` (refuses unmerged unless forced), `set_upstream`, `unset_upstream`, `merge_into_current`, `rebase_current_onto`, `checkout_and_rebase_onto_current` |
| `remote.py` | `remotes()`, `add/remove/rename/set_url`; `fetch(all, prune)`; `pull(mode: merge|rebase|ff-only, autostash)`; `outgoing(git, branch)`; `push(branch, remote, set_upstream, force_with_lease, tags)`; `delete_remote_branch`; `is_auth_error(GitError)` |
| `tags.py` | `tags()`, `create(name, sha, message?)`, `delete`, `push_tag`, `delete_remote_tag` |
| `worktrees.py` | `add(path, *, branch | new_branch+start | detach sha)`, `remove(force)`, `move`, `lock(reason)`, `unlock`, `prune`, `repair`, `summary(wt) -> WorktreeSummary(staged, unstaged, untracked, conflicts, ahead, behind, operation)`, `default_path(template, repo, branch)` |

Network commands run with `GIT_TERMINAL_PROMPT=0`; on an auth error the action offers to retry in the real terminal via `Ui.run_in_terminal`.

## Ui protocol
`Ui.form(title, fields, *, body="") -> dict | None` — generic dialog with text / checkbox / choice fields (push options, new worktree, new branch + "checkout", delete + "force"). FakeUi answers from a queue.

## Actions
- `branches.*` (screen `branches`, scope BRANCH): checkout (`enter`), new branch from (`n`), checkout & rebase onto current, compare with current (opens Log filtered `current...branch` — full compare screen in M4), rebase current onto, merge into current, pull into current (merge / rebase) for remote branches, push, rename (`F2`/`r`), delete (`delete`/`d`), favourite (`f`), set/unset upstream, new worktree from branch (`w`), delete remote branch.
- `remote.fetch` (`F`), `remote.update` (PyCharm Update Project, `ctrl+t`), `remote.push` (`P`) — push dialog lists outgoing commits per branch; `commit.commit_and_push` enabled.
- `tags.*` in branches popup Tags section: checkout, push, delete (local/remote).
- `worktree.*` (screen `worktrees`, scope WORKTREE): switch to (`enter`), new (`n` / from branch / at commit from Log), remove (`d`, offers force when dirty), move, lock/unlock (`l`), prune, repair, open shell (`s`), copy path (`y`).
- Global: `b` opens Branches popup, `w` / `alt+8` opens Worktrees window.
- Log: `log.new_worktree` ("New worktree at this commit"); worktree HEAD markers already exist (M2).
- Branch checkout of a branch checked out in another worktree → offer *Switch to that worktree*.

## UI
- `screens/branches.py` — modal popup with search box; sections Recent / Local / Remote / Tags, ★ favourites first; ahead/behind; `⎇ wt` marker for branches checked out elsewhere; registry-driven keys inside the popup (the app dispatches to any screen exposing `context()`).
- `screens/worktrees.py` — tool window table: name, path, branch/detached, dirty counts, ahead/behind, operation, lock/prunable flags; active row marked; details pane with `git status` summary.
- `dialogs.FormDialog`.

## Acceptance tests
1. refs: ahead/behind, recent order, favourites persistence, checkout remote creates tracking branch, delete unmerged refused then forced; undo of delete restores.
2. remote: fetch/pull(rebase|merge)/push against a bare remote; outgoing lists unpushed commits; force-with-lease after amend; auth error detection.
3. worktrees: add (existing branch, new branch, detached), summary counts, lock/unlock, move, remove (dirty refused, forced ok), prune after deleting a worktree dir.
4. Actions: checkout of branch held by another worktree offers switch; switch re-roots the session; `--cd-file` writes the active worktree.
5. Pilot: `b` → type to filter → `enter` checks out; `alt+8` → `n` new worktree → `enter` switches; header shows the worktree.

## As built
- Branches popup keys: `enter` checkout, `ctrl+n` new branch, `ctrl+k` push, `f2` rename, `ctrl+d` delete, `ctrl+f` favourite, `ctrl+e` compare, `ctrl+w` new worktree; everything else via `alt+enter` (Actions…). Letters always go to the search box (subsequence match, like PyCharm's speed search).
- Global: `b` branches, `w` / `alt+8` worktrees, `F` fetch, `ctrl+t` update project, `P` push; Log: `W` new worktree at commit.
- Worktrees window is a third tool-window tab; switching re-roots the session (`RepoSession.switch`) and returns to the Commit window. Removing a locked worktree asks, then uses git's double `--force`.
- "Compare with current" opens the Log filtered to `HEAD...<branch>`; the dedicated compare screen with already-picked detection is M4.
- Network actions retry in the real terminal (`Ui.run_in_terminal`) when git needs credentials.

## Later additions
- Smart / Force Checkout: when local changes block a checkout (branch, tag or Log revision) the user picks Smart (stash → switch → unstash; clashes become conflicts, stash kept) or Force (`switch --discard-changes` after a journal backup, so `z` restores). `branch.force_checkout` is also an explicit action.
- The Log has a Branches panel (`widgets/branch_panel.py`) on the left: highlighting a branch filters the log to it, `space` marks several, `[` toggles it. Branch actions apply there too (their `screens` include `log`).
