# M4 — Cherry-picking between branches

**Goal:** the user's priority workflow — pick commits from any branch quickly and safely, see what was already picked, compare branches, pick onto a branch that isn't checked out, and pick individual files/hunks.

## Backend — `git/cherry_pick.py`
| Function | Behaviour |
|---|---|
| `cherry_pick(session, shas, *, record_origin=False, no_commit=False, mainline=None)` | applies oldest → newest (callers pass log order; reversed here), `--empty=drop` so already-applied commits are skipped, writes `<git-dir>/gitpanel/sequence-total` for banner progress; returns `PickResult(status: done|conflict, state)` |
| `picked_shas(git, candidates, head="HEAD")` | commits among `candidates` whose change already exists on `head`: same `git patch-id --stable` within the last 2000 non-merge commits of `head`, or referenced by a `(cherry picked from commit …)` trailer |
| `compare(git, a, b)` | `CompareResult(only_a, only_b)` lists of `(Commit, picked: bool)` via `--left-only/--right-only --cherry-mark a...b` |
| `pick_onto_branch(session, branch, shas, **opts)` | if `branch` is checked out in a worktree → pick there (refuses if that worktree is dirty); else pick in a temporary worktree under `<git-dir>/gitpanel/pick-wt/` that is removed on success and kept (path returned) on conflict |
| `apply_from_commit(git, sha, selection)` / `get_file_from_commit(git, sha, paths)` | patch-level pick into the working tree (`--3way`), or whole-file content at that revision |

## Markers
`PickedMarkers` provider (default) marks commits not on HEAD whose change is already there: `✓ picked`, row dimmed. Cached per (HEAD sha, candidate set).

## Actions
| id | key | where | notes |
|---|---|---|---|
| `log.cherry_pick` | `C` | log, compare | selected commits onto current branch; skips picked ones unless every selected commit is already picked |
| `log.cherry_pick_options` | `alt+c` | log, compare | form: record origin (`-x`), no commit, mainline for merges |
| `log.cherry_pick_to` | `ctrl+alt+c` | log, compare | choose a local branch; uses `pick_onto_branch`; on conflict offers to switch to the worktree |
| `log.apply_changes` | `A` | log diff (HUNK) | apply the selected hunk/lines to the working tree |
| `log.get_from_revision` | `G` | log file list (FILE) | replace working-tree file with the revision's version (destructive, undoable) |
| `branch.compare` | `ctrl+e` | branches popup | now opens the Compare window |

## UI
- `screens/compare.py` — Compare window (tab appears when opened): `HEAD (main)` ↔ `<branch>` header, two commit lists ("in <branch>, not in main" / "in main, not in <branch>"), picked commits dimmed with ✓, details + diff below; `x` swaps sides; `h` hides picked commits.
- Operation banner shows `Cherry-pick (2/5) in progress` and Continue / Skip / Abort.

## Acceptance tests
1. `cherry_pick` of 3 commits from another branch applies in order; with `-x` trailers; already-applied commit dropped; conflict → `OperationState(CHERRY_PICK, step=2, total=3)`; continue after resolution.
2. `picked_shas` detects both patch-id equivalents and `-x` trailers; `compare` marks them.
3. `pick_onto_branch` onto a non-checked-out branch leaves the current worktree untouched and moves only that branch; onto a branch checked out in another worktree picks there; conflict keeps the temp worktree.
4. `apply_from_commit` with a single hunk; `get_file_from_commit`; both undoable.
5. Pilot: Log → select two commits on another branch → `C` → main has them; rows show `✓ picked`.

## As built
- Picks are ordered oldest → newest by ancestor count (`rev-list --count`), which is always topologically valid.
- `log.cherry_pick` reads the picked set from `ctx.form["picked"]` (published by the Log and Compare views from their markers) and skips those commits.
- The Compare tool window is a fourth tab; the Branches popup's `ctrl+e` opens it for `HEAD ↔ <branch>`. Both lists flag the equivalent commit on *either* side.
- Temporary pick worktrees live in `<common-dir>/gitpanel/pick-wt/<branch>`; on conflict the action offers to switch there.
