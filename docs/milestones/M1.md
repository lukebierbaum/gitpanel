# M1 — Foundations + Commit tool window

**Goal:** a runnable `gitpanel` that opens any repo (or linked worktree), shows the Commit tool window with file/hunk/line staging, commits and amends — built on the foundations from [architecture.md](../architecture.md) so later milestones only add actions, screens and marker providers.

**Out of scope for M1:** Log (M2), branches/remotes/worktree panel (M3), changelists persistence (M7, M1 shows a single "Changes" list), push (M3 — "Commit and Push" is registered but `when` returns False), undo UI (M8 — backend undo is implemented and tested here).

## Deliverables

### 0. Project skeleton
- `pyproject.toml` (already committed) → add `gitpanel/__init__.py` (`__version__`), `gitpanel/__main__.py`.
- `pixi install` → commit `pixi.lock`. `pixi run start`, `test`, `lint`, `fmt` all work.
- `scripts/make_demo_repo.sh DEST` — repo with: a few commits, a modified file with 3 separate hunks, a staged file, an untracked file, a deleted file, a rename, a binary file, and a linked worktree.
- `.github/workflows/ci.yml` — `prefix-dev/setup-pixi` (`locked: true`), `pixi run lint`, `pixi run test`, on ubuntu + macOS.

### 3. UI (`gitpanel/ui/`)
- `app.py`: `GitPanelApp(Ui)` — owns session/registry/dispatcher, tool-window tabs (only "Commit" in M1), header shows repo, active worktree path (when linked) and branch, ahead/behind.
- `keys.py` + `widgets/key_hints.py`: registry-driven key dispatch and footer.
- `palette.py`: `CommandProvider` listing `registry.available(ctx)`.
- `widgets/operation_banner.py`: shows any `OperationState`, with continue/abort buttons → actions.
- `widgets/file_tree.py`: groups **Changes** (tracked) and **Unversioned Files**; tri-state check per file (☐ none staged, ◧ partial, ☑ fully staged); directory grouping toggle; status colours (M/A/D/R/U).
- `widgets/patch_select_view.py`: diff of the focused file with per-hunk and per-line checkboxes (unified view in M1; side-by-side in M2). Shows staged vs unstaged parts of a partially staged file as one merged view: checked = in index.
- `screens/commit.py`: left = file tree, right = diff/patch view, bottom = message `TextArea` (first line ≤ 72 col ruler), options row (Amend, Sign-off, Author…), Commit button. Message history via `alt+up/down`.
- `dialogs.py`: confirm, prompt, choose, output pane — implementing the `Ui` protocol.

## Acceptance tests
Backend (`tests/git/`):
1. `parse_diff` round-trips: `build_patch(all selected)` reproduces `git diff` byte-for-byte for text files (incl. no-newline-at-EOF, CRLF, unicode paths, renames, mode changes, add/delete).
2. Stage single hunk out of 3 → `git diff --cached` contains exactly that hunk.
3. Stage single `+` line and single `-` line from a mixed hunk → index content matches expected file text.
4. Unstage a selected line of a fully staged file → `diff --cached` and `diff` both correct.
5. Rollback one hunk → worktree file equals expected; journal entry has `backup`; `undo()` restores the hunk.
6. `status` parses every porcelain v2 record type incl. unmerged and renames with spaces/newlines in paths.
7. `journal.mutation` nested → one entry; failed mutation with moved ref → recorded "(failed)"; `undo()` after commit and after amend restores HEAD/branch; `undo()` refuses when a ref moved since.
8. `operations.detect` returns correct kind/step/total for rebase (conflicting), merge, cherry-pick sequence, revert, bisect.
9. `RepoSession.open()` from inside a linked worktree finds `common_dir`, lists both worktrees, `switch()` rebinds and emits `ChangeKind.ALL`.

Actions (`tests/actions/`):
10. Registry: duplicate id rejected; `available()` respects scopes/`when`; `rebind()` overrides and unbinds.
11. Dispatcher: mutating action creates exactly one journal entry; destructive action asks `confirm` (FakeUi says no → nothing happens).

UI (`tests/ui/`):
12. Pilot: open demo repo → focus a file → `space` stages it → tree shows ☑ → type message → `ctrl+k` → `git log -1` has the message, tree empty of that file.
13. Pilot: amend toggle loads previous message; committing amends (same parent, new sha).
14. Pilot: banner appears when a merge conflict exists; abort action clears it.
